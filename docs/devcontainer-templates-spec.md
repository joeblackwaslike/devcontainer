# Dev Container Templates Specification

> Source: https://containers.dev/implementors/templates/
> Distribution: https://containers.dev/implementors/templates-distribution/

## Overview

Dev Container Templates are packaged source files that encode configuration for complete
development environments. A supporting tool uses the Template's configuration to build a
dev container. Configuration lives in `.devcontainer.json` or
`.devcontainer/devcontainer.json`, with optional supplementary files (Dockerfiles,
lifecycle scripts, stubs).

## Source Repo Layout

```
.
├── src
│   ├── template-name-1
│   │   ├── devcontainer-template.json
│   │   ├── .devcontainer/
│   │   │   └── devcontainer.json
│   │   └── [additional files]
│   ├── template-name-2
│   │   ├── devcontainer-template.json
│   │   └── .devcontainer.json
```

- The directory name must match the template's `id` field.
- All files within the template directory are packaged together.
- Multiple templates can share one repository (a "collection") under the same namespace.

## devcontainer-template.json Schema

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `id` | string | ✓ | Unique identifier — must match directory name |
| `version` | string | ✓ | Semantic version |
| `name` | string | ✓ | Human-readable name |
| `description` | string | | Brief explanation |
| `documentationURL` | string | | Link to docs |
| `licenseURL` | string | | Link to license |
| `options` | object | | Configurable options for user customization |
| `platforms` | array | | Supported languages/platforms |
| `publisher` | string | | Maintainer name |
| `keywords` | array | | Search terms |
| `optionalPaths` | array | | Files/directories tooling may omit |

## Template Options and Variable Substitution

Options enable user customization. Each option in the `options` map:

| Property | Type | Description |
|----------|------|-------------|
| `type` | string | `boolean` or `string` |
| `description` | string | User-facing explanation |
| `proposals` | array | Suggested values (free-form input still allowed) |
| `enum` | array | Strict allowed values only (no free-form) |
| `default` | string | Fallback if user doesn't select |

Options are referenced in any template file as `${templateOption:optionId}`. Supporting
tools perform string replacement across all template files when the user selects values.

### Example

```json
"options": {
  "imageVariant": {
    "type": "string",
    "description": "Specify version of Java.",
    "proposals": ["17-bullseye", "11-bullseye"],
    "default": "17-bullseye"
  },
  "installMaven": {
    "type": "boolean",
    "description": "Install Maven.",
    "default": "false"
  }
}
```

In `devcontainer.json`: `"image": "mcr.microsoft.com/devcontainers/java:${templateOption:imageVariant}"`

## Optional Paths

```json
"optionalPaths": [
  "GETTING-STARTED.md",
  ".github/*"
]
```

Directories: append `/*`. Users (or tooling via `--omit-paths`) may exclude these.

## OCI Registry Distribution

Templates distribute as tarballs: `devcontainer-template-<id>.tgz`

**Naming convention:** `<registry>/<namespace>/<id>[:version]`

Examples:
- `ghcr.io/joeblackwaslike/claude-code`
- `ghcr.io/joeblackwaslike/claude-code:1`
- `ghcr.io/joeblackwaslike/claude-code:latest`

The namespace must differ from any Feature collections in the same repo.

Custom OCI media types:
- `application/vnd.devcontainers`
- `application/vnd.devcontainers.layer.v1+tar`

## Publishing

```bash
# Publish all templates in ./src to GHCR
GITHUB_TOKEN="$CR_PAT" devcontainer templates publish \
  -r ghcr.io \
  -n joeblackwaslike \
  ./src
```

Authentication options:
- `GITHUB_TOKEN` env var (for GHCR)
- `$HOME/.docker/config.json` credentials
- `DEVCONTAINERS_OCI_AUTH=service|user|token`

## Applying a Template

```bash
# Apply with default options
devcontainer templates apply \
  -t ghcr.io/joeblackwaslike/claude-code \
  -w ./my-project

# Apply with explicit option values
devcontainer templates apply \
  -t ghcr.io/joeblackwaslike/claude-code \
  -a '{"containerName": "myproject"}' \
  -w ./my-project

# Apply and omit optional files
devcontainer templates apply \
  -t ghcr.io/joeblackwaslike/claude-code \
  --omit-paths ".devcontainer/Dockerfile" \
  -w ./my-project
```

## Versioning

Templates follow semantic versioning. Publishing tools won't republish identical versions
but must republish major and minor versions per semver rules.

## devcontainer-collection.json

Auto-generated by the publish tooling. Aggregates all templates in the collection:

| Property | Type | Description |
|----------|------|-------------|
| `sourceInformation` | object | Implementing tool metadata |
| `templates` | array | List of templates with their `devcontainer-template.json` contents |
